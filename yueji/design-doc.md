# 阅迹（Reading Trace）读书打卡系统 · 系统设计文档

> 版本：V1.0 ｜ 日期：2026-11-12 ｜ 配套原型：`阅迹-读书打卡-高保真原型.html`
> 一句话定位：**每天一刻钟，把日子过成一本书。** 以"计时打卡"为核、以"连续激励"为脉、以"共读社区"为壤的读书习惯养成工具。

---

## 1. 产品概述

### 1.1 背景与问题

| 痛点 | 阅迹的解法 |
|---|---|
| 读书难坚持，缺乏即时反馈 | 每日阅读计时 → 打卡盖章 → 积分/连续天数即时反馈 |
| 读完即忘，没有留下沉淀 | 打卡时强制/引导记录摘录 + 感想，自动归档成读书笔记 |
| 单人阅读孤独感强 | 共读圈：好友动态、摘录卡片分享、连续天数排行榜 |
| 目标感缺失 | 年度阅读计划（本数）+ 每日目标时长，双轨目标管理 |

### 1.2 目标用户

- **核心**：18–35 岁都市知识型用户，有阅读意愿但习惯不稳定；
- **次级**：重度阅读者（记录与笔记需求）、社群型用户（共读、炫耀与陪伴）。

### 1.3 核心业务闭环

```
选书入架 ──► 每日计时阅读 ──► 打卡（时长/页数/摘录/心情/星级）
    ▲                                        │
    │                                        ▼
 继续阅读/读完归档 ◄── 连续天数/积分/徽章激励 ◄── 发布到共读圈
```

### 1.4 北极指标

- **日打卡率**（DAU 中当日完成打卡占比，目标 ≥ 55%）
- 次日留存 / 7 日留存
- 打卡 → 发布笔记的转化率（衡量沉淀质量）

## 3. 打卡与激励体系设计（核心规则）

### 3.1 打卡判定

- 当日**有效打卡** = 阅读计时 ≥ 最低门槛（默认 5 分钟，可配置 5–60）；
- 阅读时长来源：App 内计时器（防作弊：屏幕锁定/切后台暂停，速度异常页数校验）；
- 当日可多次补记阅读时长，取累计值。

### 3.2 连续天数（Streak）

- 规则：当日有效打卡则连击 +1；缺卡则清零重计（补签卡可回补昨日）；
- 展示：当前连击、历史最长、超越百分比（同注册时长用户分位）；
- 缓冲机制：**补签卡**每月发放 2 张（签到/积分兑换/激励视频获得），仅可补昨日。

### 3.3 积分（书页积分）

| 行为 | 积分 |
|---|---|
| 每日打卡 | +10 |
| 阅读每满 30 分钟 | +5（上限 +15/日） |
| 记录摘录笔记 | +3/条（上限 +15/日） |
| 发布共读圈并获赞 | +1/赞（上限 +10/日） |
| 连击里程碑（7/30/100/365） | +50/+150/+500/+1500 |

积分用途：兑换补签卡、限定徽章、封面主题、共读圈虚拟书架装扮。

### 3.4 徽章（成就）

| 类别 | 示例 | 触发 |
|---|---|---|
| 连击类 | 廿日不辍 / 百日长跑 / 周年长跑 | 连续 20/100/365 天 |
| 数量类 | 破卷十二 / 汗牛充栋 | 累计读完 12/100 本 |
| 时段类 | 晨读 7 天 / 夜猫子 41 | 指定时段打卡达标 |
| 全勤类 | 全勤一月 / 全勤一季 | 自然月/季无缺卡 |
| 笔记类 | 笔记 80 条 | 累计笔记数 |

### 3.5 防沉迷与克制设计

- 每日打卡积分封顶，避免刷分；
- 社区排序权重 = 互动质量 > 连击数字，抑制纯数字内卷。

## 4. 数据模型（核心 ER）

```
User(id, nickname, avatar, level, exp, joined_at, daily_goal_min,
     streak_current, streak_best, make_up_cards, year_goal_books,
     reminder_time, privacy_mode)

Book(id, isbn, title, author, cover_url, total_pages, source[scan/search/manual])

UserBook(id, user_id, book_id, status[READING/WISH/DONE],
         current_page, started_at, finished_at, rating)

CheckIn(id, user_id, user_book_id, date, minutes, pages,
        mood, star, quote_text, quote_page, note_text(≤200),
        share_scope[PRIVATE/CIRCLE], created_at)          -- 唯一键(user_id, date, user_book_id)

StreakLog(user_id, date, type[NORMAL/MAKEUP], minutes)    -- 日粒度流水，热力图数据源

Badge(id, code, name, icon, condition_type, condition_value)
UserBadge(user_id, badge_id, unlocked_at)

FeedPost(id, check_in_id, user_id, visible_scope, like_cnt, comment_cnt)
Like / Comment / Follow(id, user_id, target_user_id, ...)

PointLog(id, user_id, action, delta, created_at)
```

> 设计要点：`CheckIn` 按日幂等（唯一键），StreakLog 单独落日表，热力图 / 排行榜直接扫该表，避免实时聚合。

## 5. API 设计（RESTful 摘要）

| 模块 | 接口 | 说明 |
|---|---|---|
| 认证 | `POST /auth/wx-login` | 微信/手机号登录，JWT |
| 书架 | `GET/POST /books`、`POST /books/scan` | 列表 / 新增 / 条码识别 |
| 书架 | `PATCH /user-books/{id}` | 更新进度 / 状态 / 评分 |
| 打卡 | `POST /checkins` | 提交打卡（幂等：同日同书覆盖累计） |
| 打卡 | `POST /checkins/timer/start·pause·stop` | 计时会话 |
| 统计 | `GET /stats/summary`、`GET /stats/calendar?month=` | 汇总 / 热力图 |
| 排行 | `GET /leaderboard?period=week|all` | 连续天数榜 |
| 社区 | `GET /feed`、`POST /feed/{id}/like` | 动态流、点赞 |
| 激励 | `GET /badges`、`POST /make-up-cards/use` | 徽章、补签 |
| 提醒 | `POST /reminders/settings` | 每日提醒配置 |

打卡核心接口示例：

```json
POST /checkins
{
  "userBookId": 1024,

  "pages": 38,
```

## 6. 系统架构

### 6.1 总体架构（单体起步，可演进微服务）

```
微信小程序 / H5 / App（Flutter 统一端）
        │ HTTPS / WSS
   CDN + WAF
        │
   API 网关（鉴权 JWT、限流、幂等键）
        │
┌───────┴────────────────────────────────────┐
│  应用层（Spring Boot 单体，模块化包）          │
│  user │ book │ checkin │ stats │ social │ gamify │
└──┬──────────┬───────────┬───────────────────┘
   │          │           │
 MySQL(主)   Redis      定时任务（XXL-Job）
 业务数据     连击缓存/   ├ 00:10 日报表聚合（streak 断签判定）
 (主从)      排行榜ZSET  ├ 08:00 阅读提醒推送
             幂等键      ├ 月初  补签卡发放 / 全勤徽章结算
                         └ 周一  周报生成
对象存储：封面、分享卡片图
推送：微信订阅消息 / APNs / 厂商通道
```

### 6.2 关键技术决策

| 决策点 | 方案 | 理由 |
|---|---|---|
| 端 | 微信小程序先行（原型按 390×844 移动端设计） | 打卡类轻应用，获客成本最低 |
| 后端 | Spring Boot 3 + MyBatis-Plus | 团队技术栈（本机已有 JDK17+Maven） |
| 连续天数 | Redis `SETNX streak:{uid}:{date}` + 定时对账 | 提交即可见，异步落库幂等 |
| 排行榜 | Redis ZSET，小时级重建 | 读多写少，前 100 热缓存 |
| 热力图 | 日表 + 按月预聚合 | 避免实时扫 CheckIn |
| 计时防作弊 | 前端心跳（30s）+ 服务端时长校验（≥心跳数） | 防脚本刷时长 |
| 幂等 | 打卡接口以 `(uid, date, bookId)` 唯一键 | 重复提交覆盖累计 |

### 6.3 打卡时序（核心链路）

```
用户 ──计时心跳──► 计时服务（校验间隔）
用户 ──提交打卡──► 打卡接口（幂等）──► 写 CheckIn + StreakLog
                      │
                      ├─► Redis 更新连击（原子 +1）
                      ├─► 积分事件 → PointLog + 等级经验
                      ├─► 徽章规则引擎（规则表化，异步判定）
                      └─► 若分享 → 生成 FeedPost + 摘要卡片图
每日 00:10 定时任务：以 StreakLog 为准对账连击，缺卡者清零并发"断签抚慰"推送
```

## 7. 非功能需求

- **性能**：打卡接口 P99 < 300ms；社区流 P99 < 500ms（缓存）；
- **一致性**：连击以定时对账结果为最终事实，允许分钟级最终一致；
- **可用性**：核心打卡链路 99.9%；定时任务失败重试 + 告警；
- **安全与隐私**：笔记默认私密，分享显式选择；UGC 先发后审 + 举报通道；
- **合规**：小程序类目（教育/阅读）、用户协议、数据删除权。

## 9. 设计规范摘要（与原型一致）

- 色板：纸白 `#FAF6EF` / 墨 `#1C1A15` / 赭红 `#B4532A`（打卡主色）/ 墨绿 `#2D6A4F`（连击达成）/ 琥珀 `#C98F2E`（成就）；
- 字体：Noto Serif SC（标题/书名/引文）+ Noto Sans SC（正文）；8pt 间距网格；圆角 8/12/18/24；
- 交互：打卡"盖章"弹出动效（spring 曲线 + 对勾描边）；触控目标 ≥ 44px；仅 toast 性轻反馈，无打断式弹窗。
